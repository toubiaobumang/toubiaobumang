# 招标条件 × 企业知识库匹配接口约定

## 目的

本文件定义“解标技能”和“企业知识库技能”之间的稳定数据接口。企业知识库回答 **我有什么**，解标模块回答 **项目要什么**，匹配模块只做 **条件 × 事实** 的可追溯判断。

## 输入：标准化招标条件

每条条件必须独立成记录，不把多个 AND/OR 条件塞进一个自然语言字符串。

建议字段：

| 字段 | 说明 |
|---|---|
| requirement_id | 条件唯一 ID，例如 Q-003 |
| requirement_type | 企业资质 / 人员 / 企业业绩 / 个人业绩 / 财务 / 信用奖项 / 设备 / 其他 |
| requirement_nature | 资格 / 否决 / 评分 / 商务响应 / 技术响应 |
| target_object | 企业 / 项目经理 / 技术负责人 / 其他人员 / 项目业绩等 |
| field | 要比较的标准字段 |
| operator | = / != / >= / <= / contains / in / exists / date_after / date_before |
| expected_value | 标准化目标值 |
| unit | 万元、㎡、年等；无单位留空 |
| time_start | 时间范围起点；可精确到日时建议使用 `YYYY-MM-DD`，无明确起点留空 |
| time_end | 时间范围终点；可精确到日时建议使用 `YYYY-MM-DD`，无明确终点留空 |
| required_count | 需要满足的数量 |
| evidence_requirement | 招标文件明确要求的证明材料 |
| source_location | 条件在招标文件中的页码/章节 |
| raw_text | 原始条款，供人工复核 |
| parent_group | 复合条件所属父组 ID；无父组留空 |
| logic | 同一父组内逻辑关系：`AND / OR`；非复合条件留空 |

## 查询：只查“可投标匹配事实”

匹配模块优先查询 `03_结构化索引与台账/投标事实索引.csv` 及对应专业台账。

不得把以下内容当作已满足：

- `待核验`、`历史`、`失效`、`版本冲突` 的事实；
- 只有摘要、没有原始来源的事实；
- 已过有效期的证书/证明；
- 数值、时间、工程类别等关键字段缺失时的猜测；
- 仅有单一材料而招标条件明确要求完整证据组合的情形。

## 输出状态

只允许：

- `满足`：字段条件满足，必要证据链达到可用标准；
- `不满足`：已有可靠事实明确不满足；
- `待核验`：候选事实存在，但证据、版本、有效期或关键字段不足；
- `未发现`：在已检查范围内未找到可匹配事实；不得等同“企业没有”。

## 输出最小结构

```yaml
requirement_id: Q-003
match_status: 满足
matched_objects:
  - object_id: PERF-001
    object_name: XX冷链物流项目
    matched_fields:
      工程类别: 公共建筑
      合同金额: 8200万元
      竣工日期: 2024-05-18
    evidence_grade: A
    evidence:
      - 01_企业原始资料库/.../中标通知书.pdf
      - 01_企业原始资料库/.../施工合同.pdf
      - 01_企业原始资料库/.../竣工验收.pdf
gaps: []
notes: ""
```

## AND / OR / 数量规则

- AND：所有子条件均满足，父条件才可标记 `满足`。
- OR：至少一个子条件满足即可，但输出必须说明采用了哪一个分支。
- 数量：例如“3项业绩”，必须有 3 个不同、可识别的业绩对象达到要求。
- 同一项目的多份证明材料不计算为多项业绩。
- 同一人员不同证书不计算为多名人员。

## 评分项

知识库可以返回“可用于评分计算的候选事实”，但不得在缺少完整评分规则时自行宣称最终得分。

当评分规则完整时，输出应区分：

1. 条件事实是否满足；
2. 可计分数量；
3. 按规则计算的理论分值；
4. 待核验项对分值的影响。

## 证据回查

每个 `满足` 或 `待核验` 结论都必须至少返回：

- 对象 ID；
- 来源文件；
- 正式归档路径；
- 对应页码/章节/表格等定位（能获取时）；
- 证据等级；
- 最近核验日期。
