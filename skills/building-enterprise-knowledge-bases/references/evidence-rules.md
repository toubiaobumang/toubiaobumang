# 证据、状态与可追溯规则

## 事实源

`01_企业原始资料库` 中的真实企业文件是长期事实源。`02_AI企业知识库`、`03_结构化索引与台账`、AI 摘要和历史回答都不是独立事实源。

## 事实状态

事实状态为受控字段，只使用：`已确认 / 待核验 / 历史 / 失效 / 版本冲突 / 缺失 / 不适用`。

- `已确认`：有直接、可定位的真实来源支持，且当前没有已知冲突。
- `待核验`：证据不完整、关键字段缺失、归属不确定、需外部核验或版本不明。
- `历史`：曾经成立但已被新版本或新状态替代，仅用于追溯；完成的历史项目/业绩如仍是有效投标事实，不应仅因时间久而标为 `历史`。
- `失效`：原本有效，但因到期、撤销、注销或其他明确原因已不能按当前有效事实使用。
- `版本冲突`：两个或以上来源对关键字段存在未解决冲突。
- `缺失`：业务明确需要，且在约定资料范围完成检查后仍未发现。
- `不适用`：确认与当前对象或业务场景无关。

`未发现` 是查询/匹配结果状态，不是事实状态。只有在约定资料范围已完成检查且业务明确需要时，才可形成 `缺失` 待补项；“没有搜索到”不能直接推导“企业没有”。

## 证据完整度 A/B/C/D

证据完整度描述“当前证据链完整程度”，不替代招标文件自己的证明材料要求。

- `A`：关键事实有直接原始证据，必要的核心证明链完整，无已知冲突，日期/有效期可判断。
- `B`：关键事实有直接原始证据，但辅助材料、官方查询、部分链路或定位仍可补强。
- `C`：仅有部分或间接证据；存在关键字段/关键证明缺口，不能据此直接宣称完整满足投标条件。
- `D`：来源不可用、严重冲突、已失效、无法读取，或无法可靠归属到该对象。

同一对象可以有多个事实、多个证据等级。不要因为“这个项目总体是 A”就自动把项目所有字段都视为 A。

## 建筑投标常见证据链

### 企业资质

`资质证书 → 有效期/现行状态 →（必要时）官方核验来源`

### 投标人员

`人员身份 → 注册证/职称 → 安全证 → 社保或劳动关系 → 在职状态 →（若要求）个人业绩`

### 企业业绩

常见链路：

`中标通知书 → 合同 → 验收/竣工材料 →（若招标要求）官方平台查询证明`

这不是固定法律规则。最终是否满足必须回到当前招标文件明确要求的证明材料组合。

## 来源记录

关键事实至少记录：原始文件名、正式归档路径、原始来源路径（如有）、文件日期/版本、支撑字段、来源定位。长文档优先记录页码、章节、表格或可复核锚点。

## 冲突处理

1. 不静默选一个答案。
2. 保留双方来源和冲突字段。
3. 写入版本冲突清单或待人工核验。
4. 只有正式生效信息足以解决时才更新现行状态。
5. 无法解决时保持 `版本冲突/待核验`，并禁止作为确定匹配事实。

## 投标匹配闸门

标记某条件 `满足` 前至少检查：

1. 标准字段确实满足条件；
2. 对象身份和归属明确；
3. 时间窗口和有效期满足；
4. 招标文件要求的证明材料已找到或达到约定证据条件；
5. 不存在未解决的关键冲突。

任一关键项不成立，应输出 `不满足`、`待核验` 或 `未发现`，不能用“看起来差不多”补齐。

## 禁止

- 补造编号、日期、金额、面积、资质、人员、业绩或参数；
- 从文件名直接认定内容事实；
- 用 AI 旧摘要当新证据；
- 把营业执照经营范围当专业资质；
- 把企业项目自动算作某个人员的个人业绩；
- 把待核验事实写成“满足”。
