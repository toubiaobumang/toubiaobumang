# 投标企业知识库自动建库与归档

## 核心目标

把企业长期积累的人员、资质、业绩、合同、奖项、财务、设备、技术方案等文件，维护成一套 **可检索、可追溯、可持续更新、可被招标条件直接反查** 的企业投标数据底座。

完成标准不是“文件分好类”，而是：新的招标条件到来时，可以结构化回答 **企业有什么、哪些候选对象可能满足、证据在哪里、还缺什么**。

## 固定骨架

一级目录保持稳定：

```text
企业知识库/
├─00_待整理入口
├─01_企业原始资料库
├─02_AI企业知识库
├─03_结构化索引与台账
├─04_当前项目工作区
├─05_知识库维护与审计
└─99_待识别与异常资料
```

详细架构读取 `references/kb-architecture.md`。

## 初始化

行业未确认时只建通用骨架：

```bash
python scripts/initialize_kb.py "<企业知识库根目录>"
```

已确认是建筑、工程、施工或招投标企业时，使用：

```bash
python scripts/initialize_kb.py "<企业知识库根目录>" --profile construction-bidding
```

脚本只创建缺失目录和空表，不覆盖已有业务文件。

## 开始前必须遵守

1. 只处理用户明确授权的工作空间，不扫描整台电脑。
2. `00_待整理入口` 视为用户明确提交给本技能整理的资料入口。
3. 知识库外的唯一原件默认复制纳入，不擅自移动或删除。
4. 删除、覆盖、批量清理等不可逆操作必须单独确认。
5. 原始文件是事实源；AI 摘要、知识页和 CSV 只是结构化表达。
6. 不确定就标记 `待核验/未发现/版本冲突`，不得补造事实。

读取：

- 分类：`references/classification-rules.md`
- 实体：`references/entity-model.md`
- 证据：`references/evidence-rules.md`
- 审计：`references/audit-rules.md`
- 建筑投标字段：`references/industry-expansion.md`
- 招标匹配接口：`references/bid-matching-contract.md`

## 执行流程

### 1. 初始化或识别现有知识库

确保固定骨架存在。空库只创建空目录、空台账和说明，不虚构企业、人员、项目或资质。

### 2. 盘点本轮资料

优先处理：

- `00_待整理入口`；
- 知识库根目录中的散落业务文件；
- 用户明确指定的导入来源。

已有稳定归档且本轮未变化的文件不重复全文处理。

可使用：

```bash
python scripts/inventory.py "<待处理范围>" --output "<05_知识库维护与审计>/本次文件盘点.json"
```

### 3. 识别业务对象并唯一归档

按“实际内容 → 业务对象 → 文档用途 → 业务场景 → 元数据 → 文件名”判断。

高置信度资料进入 `01_企业原始资料库` 的唯一正式位置；多重用途通过索引和关系表达，不复制多个正式副本。低置信度、损坏、冲突或归属不明文件进入 `99_待识别与异常资料`。

### 4. 建立实体和原子事实

先建立企业、人员、资质、项目、业绩、合同、客户等实体，再拆出可比较事实。

例如：

```text
XX项目 → 合同金额 → 8200万元
XX项目 → 建筑面积 → 18600㎡
张三   → 注册专业 → 建筑工程
```

一条事实必须可追溯到原始资料。多值属性拆成多条事实，不把不可计算的长列表塞入单一字段。

### 5. 建筑投标专业抽取

识别为建筑/工程/招投标企业时，必须维护：

- 投标事实索引；
- 企业资质；
- 投标人员；
- 企业业绩；
- 个人业绩；
- 信用奖项；
- 财务税务保险；
- 设备资源；
- 技术方案索引。

字段、标准化和证据链规则读取 `references/industry-expansion.md`。

关键约束：

- 营业执照经营范围不能代替专业资质；
- 企业项目不能自动变成人员个人业绩；
- 只有年份/月的日期不能补成具体日；
- 金额、面积、长度等数值必须保留单位和原始值；
- 关键字段缺失时不得估算。

### 6. 更新 `投标事实索引.csv`

这是下游反查的主查询层。一行只表达一个 `对象—属性—值`，并记录：事实状态、证据等级、来源文件、正式路径、来源定位、最后核验日期、是否可用于投标匹配。

`投标事实索引` 不能反向成为事实源；任何结论仍需回查 `01_企业原始资料库`。

### 7. 更新 AI 知识页

`02_AI企业知识库` 使用普通 Markdown，面向人和 AI 阅读，负责总览、实体档案、经验摘要和专题导航。

知识页可以总结，但每个关键结论必须能回到原始证据和结构化事实。

### 8. 证据评级与冲突处理

按 `references/evidence-rules.md` 标记：

- 事实状态：`已确认 / 待核验 / 历史 / 失效 / 版本冲突 / 缺失 / 不适用`；
- 证据完整度：`A / B / C / D`。

证据等级描述完整程度，不替代当前招标文件自己的证明材料要求。

### 9. 审计与增量维护

至少检查：来源断链、版本冲突、证照过期/临期、关键资料缺口、重复文件、索引与原始资料不一致、待整理入口残留、投标专业台账关键字段缺失。

可运行：

```bash
python scripts/hash_duplicates.py "<01_企业原始资料库>" --output "<05_知识库维护与审计>/重复文件哈希.json"
python scripts/validate_structure.py "<企业知识库根目录>" --profile construction-bidding
```

每轮更新追加 `05_知识库维护与审计/知识库更新日志.md`。

### 10. 投标匹配就绪验收

对建筑/工程/招投标企业，除了结构完整，还必须抽查以下问题能否用真实证据回答：

1. 当前有哪些有效企业资质？
2. 哪些人员可作为某类岗位的候选人，其注册证、安全证、社保状态分别是什么？
3. 哪些企业业绩能按工程类别、金额、规模、时间筛选？
4. 哪些个人业绩能明确绑定到“人员 + 项目 + 角色 + 证明”？
5. 哪些业绩/人员证据链不完整？
6. 随机抽取至少 5 条关键事实，是否能回到原始文件和定位？
7. 给定一组标准化招标条件，是否能按 `满足 / 不满足 / 待核验 / 未发现` 返回候选对象、证据和缺口？

若只能“搜到文件”，但不能做上述筛选和证据回查，则不能标记为“投标匹配就绪”。

## 与解标/匹配技能的边界

本技能负责 **我有什么**。它可以接受标准化招标条件进行查询，但不应凭空解释一份复杂招标文件。

推荐下游链路：

```text
招标文件
→ 解标：它要什么
→ 标准化 requirement
→ 企业知识库：我有什么
→ 匹配：满足 / 不满足 / 待核验 / 未发现
→ 返回候选对象 + 证据 + 缺口
```

接口格式读取 `references/bid-matching-contract.md`。

在评分规则不完整时，只返回可计分候选事实，不自行宣称最终得分。

## 三种运行模式

- **空库初始化**：建空骨架，不虚构实体。
- **首次全量整理**：盘点、唯一归档、实体化、事实化、建台账和知识页。
- **增量更新**：优先处理新文件和变化文件，只更新受影响实体、事实、证据和日志。

## 完成条件

只有当 **原始资料、实体、原子事实、结构化台账、AI知识页、证据状态、审计结果和更新日志一致** 时，本轮维护才算完成；建筑投标企业还需通过“投标匹配就绪验收”。
